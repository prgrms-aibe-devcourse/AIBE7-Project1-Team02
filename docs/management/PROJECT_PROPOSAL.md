# 프로젝트 기획안

## 1. 프로젝트명

Packing

## 2. 기획 배경

국내 여행을 준비할 때 사용자는 여행지 탐색, 취향에 맞는 장소 선별,
일정 구성, 저장과 공유를 여러 서비스에서 따로 처리해야 합니다. 특히
관광지 정보가 많아질수록 사용자는 자신에게 맞는 장소를 고르기 어렵고,
추천 서비스가 제공하는 기준도 명확하지 않은 경우가 많습니다.

Packing은 사용자의 여행 성향을 먼저 분석하고, 실제 공공 관광 데이터를
기반으로 추천과 일정 생성을 연결해 여행 준비 과정을 하나의 흐름으로
줄이는 것을 목표로 기획했습니다.

## 3. 문제 정의

- 사용자는 많은 관광지 중 자신의 취향에 맞는 장소를 고르기 어렵다.
- 단순 인기순 추천은 개인의 여행 스타일을 충분히 반영하지 못한다.
- 여행지 탐색과 일정 생성이 분리되어 있어 사용자가 직접 다시 조합해야 한다.
- AI가 임의로 존재하지 않는 장소를 생성하면 여행 일정의 신뢰도가 떨어진다.
- 무료 API와 BaaS 환경에서는 데이터 조회량과 호출량 관리가 중요하다.

## 4. 서비스 목표

Packing의 목표는 MBTI 기반 여행 성향 분석, 실제 관광지 데이터, 일정
생성 기능을 결합해 사용자가 더 적은 탐색 비용으로 자신에게 맞는 국내
여행 계획을 만들 수 있게 하는 것입니다.

주요 목표:

- 사용자의 여행 성향을 간단한 설문으로 분류한다.
- TourAPI 기반 관광지 데이터를 서비스용 데이터로 가공한다.
- MBTI 유형별 적합도 점수를 활용해 맞춤 여행지를 추천한다.
- 추천된 여행지를 바탕으로 최대 7일의 여행 일정을 생성한다.
- 생성한 일정과 저장한 관광지를 마이페이지에서 관리한다.

## 5. 핵심 사용자

| 사용자 | 니즈 |
| --- | --- |
| 여행지를 고르기 어려운 사용자 | 자신의 취향에 맞는 국내 관광지를 빠르게 추천받고 싶다. |
| 일정을 직접 짜기 번거로운 사용자 | 지역, 기간, 동행 유형만 입력해 기본 일정을 만들고 싶다. |
| 여행 후보지를 모아두고 싶은 사용자 | 마음에 드는 관광지를 북마크하고 나중에 다시 보고 싶다. |
| 여행 경험을 공유하고 싶은 사용자 | 커뮤니티에서 여행 기록이나 장소를 공유하고 싶다. |

## 6. 핵심 가치

### 개인화

사용자의 여행 MBTI를 기준으로 관광지 추천과 일정 생성 흐름을 연결합니다.
MBTI는 심리 진단이 아니라 여행 취향을 분류하기 위한 기준으로 사용합니다.

### 신뢰성

AI가 임의의 장소를 만들어내는 방식을 지양하고, 한국관광공사 TourAPI에서
수집한 실제 관광지 데이터를 기반으로 추천과 일정을 구성합니다.

### 사용성

추천, 필터 탐색, 북마크, 일정 생성, 일정 확인을 하나의 서비스 흐름으로
연결해 사용자가 여러 도구를 오가며 직접 조합해야 하는 부담을 줄입니다.

### 비용 효율

외부 API를 사용자 요청마다 호출하지 않고 Supabase에 사전 저장한 관광지
데이터를 조회합니다. 목록 조회는 페이지네이션하고, 필터 옵션도 필요한
값만 가져오도록 설계해 무료 사용량을 고려했습니다.

## 7. 주요 기능 기획

### 7.1 여행 성향 분석

사용자는 12개 문항에 응답하고, 서비스는 활동/휴식, 전통/탐험,
효율/감성, 계획/즉흥 4개 축의 점수를 계산합니다. 결과는 MBTI 16유형과
여행가 칭호로 표시되며, 이후 추천 기준으로 사용됩니다.

### 7.2 맞춤 여행지 추천

로그인 사용자는 자신의 MBTI 결과에 맞는 TOP 10 여행지를 카드 슬라이드로
확인합니다. 비로그인 사용자는 공개 추천 기준으로 여행지 더 찾아보기
페이지를 이용할 수 있습니다.

### 7.3 여행지 더 찾아보기

사용자는 전체 관광지를 페이지 단위로 탐색하고, 지역과 키워드를 복수
선택해 필터링할 수 있습니다. 전체 탐색 화면에서는 점수나 랭킹을 직접
노출하지 않고, 사용자가 여행지 자체의 정보에 집중하도록 구성했습니다.

### 7.4 북마크

로그인 사용자는 관심 있는 여행지를 저장할 수 있으며, 마이페이지에서
저장한 여행지를 모달 형태로 다시 확인할 수 있습니다.

### 7.5 여행 일정 생성

사용자는 지역, 시작일, 종료일, 동행 유형, 선택 키워드를 입력해 최대
7일의 여행 일정을 생성합니다. 일정에는 이미지가 있는 실제 관광지만
포함하고, 같은 관광지가 중복되지 않도록 구성합니다.

Gemini API 호출이 실패하거나 할당량을 초과하면 자체 fallback 로직으로
일정을 생성해 서비스 흐름이 중단되지 않도록 설계했습니다.

### 7.6 여행 일정 확인

저장된 일정은 시작 전, 진행 중, 완료 상태로 관리됩니다. DAY별 상세
모달에서 관광지 목록과 Kakao 지도 마커를 확인하고, 진행 중 일정에서는
관광지별 완료 처리를 할 수 있습니다.

### 7.7 마이페이지와 커뮤니티

마이페이지에서는 프로필, 여행가 칭호, 저장한 관광지, 완료한 여행,
약관 확인, 데이터 초기화와 회원 탈퇴를 제공합니다. 커뮤니티에서는
게시글, 댓글, 좋아요, 공유, 이미지 업로드를 통해 사용자 간 여행 경험을
나눌 수 있습니다.

## 8. 데이터 기획

TourAPI 원본 데이터는 그대로 사용하지 않고, 서비스 추천에 필요한 형태로
가공합니다.

처리 방향:

- 주소, 이미지, 좌표, 설명이 있는 관광지만 저장
- `province`, `city` 기준으로 국내 행정구역 정규화
- 관광지명, 설명, 카테고리 코드를 기반으로 서비스 키워드 생성
- MBTI 16유형별 적합도 점수 계산
- 사용자 요청 시 외부 API가 아니라 Supabase의 가공 데이터를 조회

이 방식은 추천 기준을 통제할 수 있고, API 응답 속도를 안정화하며,
외부 API 호출량을 줄이는 장점이 있습니다.

## 9. 기술 기획

| 영역 | 기획 방향 |
| --- | --- |
| Frontend | HTML, CSS, Vanilla JavaScript 기반의 경량 Multi-page 구조 |
| Backend | Node.js와 Express로 API 라우팅과 비즈니스 로직 처리 |
| Database/Auth | Supabase PostgreSQL, Auth, Storage 활용 |
| AI | Gemini API를 일정 생성 보조로 사용하고 fallback 로직 유지 |
| Map | Kakao Maps JavaScript API로 일정 위치 시각화 |
| Deployment | Render Web Service로 Node.js 서버 배포 |

## 10. 기대 효과

- 사용자는 자신의 여행 성향에 맞는 관광지를 빠르게 탐색할 수 있다.
- 추천과 일정 생성이 연결되어 여행 준비 시간을 줄일 수 있다.
- 실제 관광지 데이터 기반으로 일정 신뢰도를 높일 수 있다.
- 북마크와 마이페이지를 통해 여행 후보와 완료 여행을 관리할 수 있다.
- 팀은 데이터 가공, RLS, OAuth, 배포, 테스트 등 실서비스 흐름을 경험할 수 있다.

## 11. MVP 범위

포함 범위:

- 국내 여행만 지원
- MBTI 기반 여행 성향 분석
- TourAPI 기반 관광지 추천
- 지역·키워드 필터
- 북마크
- 최대 7일 여행 일정 생성
- 일정 저장·조회·상태 변경·삭제
- 마이페이지
- 커뮤니티 기본 기능
- Render 배포

제외 범위:

- 해외 여행
- 실제 교통수단 기반 이동 시간 계산
- 숙박, 항공, 결제
- 실시간 날씨와 혼잡도 반영
- 완전한 E2E 자동화

## 12. 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 외부 API 호출량 제한 | TourAPI 데이터를 사전 적재하고, 지역·유형별 분산 수집 적용 |
| Supabase 무료 사용량 초과 | 페이지네이션, 필요한 컬럼만 조회, 새 프로젝트 이전 대비 migration 정리 |
| AI 응답 실패 또는 quota 초과 | 자체 fallback 일정 생성 로직 유지 |
| OAuth와 RLS 설정 오류 | Auth trigger, policy, grant를 migration과 문서에 반영 |
| 일정 테이블 과도기 구조 | 향후 `trips`와 `trip_plans` 단일화 계획 수립 |

## 13. 향후 발전 방향

- 일정 데이터 모델 단일화
- AI Provider 교체 가능한 `src/services/ai` 구조 도입
- TourAPI 정기 갱신 자동화
- 실제 이동 시간, 운영 시간, 날씨를 반영한 경로 최적화
- 사용자 북마크와 완료 여행 기록을 반영한 추천 점수 보정
- E2E 테스트와 배포 QA 자동화
