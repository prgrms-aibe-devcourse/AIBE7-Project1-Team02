# 요구사항 명세서

## 1. 문서 개요

본 문서는 Packing 서비스의 MVP 구현 범위와 배포 완료 시점의 요구사항을
정리합니다. 서비스는 대한민국 국내 여행을 대상으로 하며, 사용자의 여행
성향 분석 결과와 실제 관광지 데이터를 활용해 맞춤 여행지 추천, 일정
생성, 저장, 커뮤니티 기능을 제공합니다.

## 2. 서비스 개요

Packing은 사용자의 여행 성향을 MBTI 기반으로 분석하고, 한국관광공사
TourAPI 데이터를 가공해 개인화된 국내 관광지를 추천하는 웹 서비스입니다.
사용자는 추천 관광지를 탐색하고 북마크할 수 있으며, 지역·기간·동행
유형·키워드에 맞는 여행 일정을 생성하고 저장할 수 있습니다.

## 3. 사용자 범위

| 사용자 | 설명 |
| --- | --- |
| 비회원 사용자 | 로그인 없이 공개 추천 기준의 여행지 탐색 가능 |
| 회원 사용자 | 성향 분석, 추천, 북마크, 일정 생성·저장, 마이페이지, 커뮤니티 사용 |
| 관리자성 서버 작업 | 관광지 데이터 적재, 사용자 데이터 초기화, 회원 탈퇴 처리 |

## 10. 제약사항 및 향후 개선

| 구분 | 내용 |
| --- | --- |
| 일정 데이터 모델 | 현재 `trips`와 `trip_plans`를 함께 사용하는 과도기 구조이며 향후 단일화 필요 |
| AI Provider 구조 | Gemini 호출이 일부 travel route 흐름에 남아 있어 Provider 교체형 구조로 분리 필요 |
| 데이터 최신성 | TourAPI 정기 갱신 자동화가 필요 |
| 경로 최적화 | 실제 이동 시간, 운영 시간, 날씨를 반영한 고도화 필요 |
| 테스트 | 핵심 로직 테스트는 있으나 E2E 자동화는 향후 과제 |
| 배포 운영 | 무료 사용량 초과에 대비해 Egress, DB 백업, migration 검증 절차 필요 |

## 11. 완료 기준

- 사용자는 회원가입 또는 OAuth 로그인 후 약관 동의와 프로필 설정을 완료할 수 있다.
- 사용자는 성향 분석을 완료하고 자신의 여행가 칭호와 추천 여행지를 확인할 수 있다.
- 사용자는 여행지를 필터링하고 상세정보와 북마크를 사용할 수 있다.
- 사용자는 최대 7일의 여행 일정을 생성, 저장, 조회, 상태 변경, 삭제할 수 있다.
- 사용자는 마이페이지에서 북마크와 완료한 여행을 확인할 수 있다.
- 사용자는 커뮤니티에서 게시글과 댓글 중심의 기본 활동을 할 수 있다.
- 서비스는 Render 배포 환경에서 주요 MVP 흐름을 실행할 수 있다.
