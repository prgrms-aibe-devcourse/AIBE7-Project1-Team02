# 아키텍처 의사결정 기록

## 공통 목표

Packing은 교육용 MVP의 제한된 기간과 예산을 고려해 **실제 지출 비용
0원**으로 개발하고 배포하는 것을 목표로 했습니다. Supabase, Render,
Gemini의 무료 티어와 한국관광공사 TourAPI를 활용했으며, 비용이 발생하지
않는 범위에서 서비스의 핵심 기능을 구현했습니다.

## ADR-001: Supabase 선택

- **결정**: 인증, PostgreSQL, Storage에 Supabase 무료 티어를 사용한다.
- **이유**: 별도 인증 서버와 DB 인프라 없이 이메일·소셜 로그인, RLS,
  관계형 데이터, 이미지 저장을 빠르게 구축할 수 있다.
- **결과**: 초기 인프라 구축 비용 없이 MVP를 완성했다.
- **한계**: 무료 Egress 한도를 초과해 프로젝트를 이전했으며, migration
  관리의 중요성을 확인했다.

## ADR-002: TourAPI 데이터 사전 적재

- **결정**: 사용자 요청마다 TourAPI를 호출하지 않고 관광지 데이터를
  Supabase에 미리 저장해 사용한다.
- **이유**: 무료 API 호출량과 응답 지연을 줄이고, 주소·이미지·설명을
  검증한 뒤 키워드와 MBTI 점수를 사전에 가공하기 위함이다.
- **결과**: 추천 요청은 가공된 DB 데이터를 조회하므로 일관된 결과와
  빠른 응답을 제공할 수 있다.
- **한계**: 관광지 최신성을 유지하려면 재적재 또는 정기 배치가 필요하다.

## ADR-003: Gemini fallback 적용

- **결정**: Gemini 일정 생성이 실패하면 자체 규칙 기반 일정 생성기로
  전환한다.
- **이유**: 무료 티어의 요청 제한, 네트워크 오류, 응답 형식 오류가 핵심
  일정 생성 기능의 전체 실패로 이어지는 것을 방지하기 위함이다.
- **결과**: AI 사용 비용 없이 일정 생성 기능을 제공하면서도 장애 시
  서비스 흐름을 유지할 수 있다.
- **한계**: fallback 결과는 AI 결과보다 설명의 다양성과 유연성이 낮을
  수 있다.

## 최종 판단

무료 티어와 공공 API를 조합해 **인프라, 데이터 API, AI API, 배포 비용을
포함한 프로젝트 직접 지출 비용을 0원으로 유지**했습니다. 대신 무료
한도와 외부 서비스 의존성을 고려해 페이지네이션, 데이터 사전 적재,
fallback, migration 관리가 필요했습니다.
